## Strongest Current Diagnosis
The most likely core bug is in:
- `lib/Dialect/TritonNvidiaGPU/IR/TensorMemoryUtils.cpp`
- `getTMemLdStRowPlanForQueryLayout(...)`

Why:
- for projected `64x32xf32` M64 direct loads, the planner likely needs the projected `layoutPlan` (`16,32,64` class)
- current logic appears to over-preserve the root/backing `32,64,128` contract when an explicit physical layout matches the query layout
- that lines up with the current codegen drift:
  - merge-base `test_mma_shared_inputs[...]` uses packed `16x32bx2.x16`
  - current-head uses scalar `32x32b.x1`
  - merge-base multicta uses packed `16x32bx2.x16`
  - current-head multicta uses `16x32bx2.x8 + x8`

## Specific Patch I Was About To Make
In `getTMemLdStRowPlanForQueryLayout(...)`:
- remove the early rule that returns `backingPlan` when `explicitPhysicalLayout.layout == queryLayout.layout`
- broaden the existing projected-M64 override so **any** projected M64 query returns `layoutPlan` when:
  - rank is `2`
  - element bitwidth is `32`
  - shape[0] is `64`
  - `layoutPlan->rowSpan == 64`
  - `layoutPlan->rowSpan < queryPlan->rowSpan`
