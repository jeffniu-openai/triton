# Round 30 Direct Branch `tcgen05.copy` Illegal-Index Minimization

Date: 2026-04-21

Mode: discovery/cataloging only. No backend or compiler code was modified.

## Scope

This lane minimized the Round 29 direct distinct-branch `tcgen05.copy` finding:
direct branch `tmem_load`, `tmem_store`, and `ld.red` controls pass, but a
direct branch-selected descriptor feeding `ttng.tmem_copy` can leave an illegal
`ttg.memdesc_index` for LLVM conversion.

The probe varied:

- selector `0` and selector `1`;
- copy with readback and copy without TMEM readback;
- 1CTA and 2CTA TMEM layouts;
- same parent object with distinct indices;
- same parent object with the same index on both branches;
- distinct unindexed TMEM objects;
- same index from different parent objects.

## Results

| Row | Selector | Readback | CTA mode | Result |
| --- | --- | --- | --- | --- |
| same parent, distinct indices | 0 | no | 1CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 0 | yes | 1CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 1 | no | 1CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 1 | yes | 1CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 0 | no | 2CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 0 | yes | 2CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 1 | no | 2CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |
| same parent, distinct indices | 1 | yes | 2CTA | LLVM conversion failure: illegal `ttg.memdesc_index` |

The same run showed green contrasts:

| Row | Result |
| --- | --- |
| same parent, same index on both branches | passed for selector 0/1, readback on/off, 1CTA/2CTA |
| distinct unindexed TMEM objects | passed for selector 0/1, readback on/off, 1CTA/2CTA |

The same-index different-object row exceeded TMEM capacity at `N=128` because
it allocates two `2xM x N` parents. The `N=32` rerun removed that resource
confounder:

| Row | Result |
| --- | --- |
| same parent, distinct indices | still failed for selector 0/1, readback on/off, 1CTA/2CTA |
| same parent, same index on both branches | passed for all selector/readback/CTA combinations |
| distinct unindexed TMEM objects | passed for all selector/readback/CTA combinations |
| same index from different parent objects | passed for all selector/readback/CTA combinations |

Every passing row had zero mismatches. Passing same-index branch rows still had
two `ttg.memdesc_index` ops in TTGIR, but zero `ttg.memdesc_index` ops in LLIR.
That is the important contrast: branch selection itself can survive when the
indices collapse to the same logical view, while selecting different indices of
the same parent leaves a dynamic memdesc index live into LLVM conversion.

## TTGIR Before LLVM

The failing reproducer generated by the compiler is:

```text
/tmp/tmem_copy_branch_round30/repro_n32.make_llir.repro.mlir
```

Relevant lines:

```text
%3 = ttg.memdesc_index %result[%2] : !ttg.memdesc<2x256x32xi32, ...> -> !ttg.memdesc<256x32xi32, ...>
ttng.tmem_copy %15, %3 : !ttg.memdesc<256x32xi32, #shared, #smem, mutable>, !ttg.memdesc<256x32xi32, #tmem_linear1, #ttng.tensor_memory, mutable>
```

The failing shape has already reached the `make_llir` input with a dynamic
`ttg.memdesc_index` feeding `ttng.tmem_copy`. The later failure is therefore not
a frontend-only issue and not a copy opcode verifier rejection; the unresolved
descriptor index survives until `ConvertTritonGPUToLLVM`, where
`ttg.memdesc_index` is explicitly illegal.

The passing same-index branch rows provide the direct TTGIR/LLIR contrast:

```text
ROW same_object_same_index ... PASS mismatch=0 ttgir_memdesc_index=2 ttgir_copy=1 llir_memdesc_index=0
```

## Classification

No new independent `FZ-*` bucket is proposed.

This lane sharpens existing `FZ-20260421-0001`:

- the failing minimum is a same-parent, branch-selected, distinct-index
  descriptor feeding `ttng.tmem_copy`;
- the failure does not require TMEM readback after the copy;
- the failure reproduces for both selector values;
- the failure reproduces for both 1CTA and 2CTA TMEM layouts;
- the failure is not caused by branching on memdesc values in general, because
  same-index branch selection and distinct-object branch selection pass;
- the failure is not a resource issue, as the `N=32` matrix passes all controls
  and still fails the same-parent distinct-index row.

Working hypothesis for the eventual fix phase: the planner/legalizer has a
canonicalization path that can discharge branch-local static indices when both
branches resolve to the same index, and it can treat branch-selected whole TMEM
objects without memdesc indexing. It does not have an equivalent lowering for a
dynamic selection between different slices of the same parent descriptor before
copy lowering.
