# PTX ISA 9.2 Blackwell Float2 Research

## f32x2 arithmetic on Blackwell
PTX provides `.f32x2` variants of `add`, `sub`, `mul`, and `fma` that treat each operand as a single `.b64` register containing two packed `.f32` values and execute each lane in parallel.  These instructions honor the usual rounding modifiers (`.rn/.rz/.rm/.rp`), can optionally flush subnormals with `.ftz`, and support `.sat` (clamping to `[0, 1]` for `NaN`-aware results) so that the behavior of each lane mirrors the scalar counterparts while staying in a single instruction.  All of the `.f32x2` forms require `sm_100` or higher, so they are available on any Blackwell-class (sm_100-series) device, and the writer can therefore reason about two-lane processing without falling back to scalar loops.citeturn3view0

## Min/max, clamping, and special modifiers
`min`/`max` are only defined for scalar floating-point values, but their qualifiers (`.NaN`, `.abs`, and for `max` also `.xorsign` and the three-input form) were introduced before or alongside the Blackwell class, so the richer saturation semantics are available in our kernels.  The `.NaN` variant canonicalizes results to a canonical NaN, `.abs` can be used for positive-magnitude comparisons, `.xorsign` manipulates sign bits, and the three-input `max` (introduced in PTX 8.8) lets us compare more than two values in hardware.citeturn5view0

## Packed conversions and saturation helpers
PTX's `cvt` instructions can pack two lanes at once (`.f16x2`, `.bf16x2`, `.s2f6x2`, `.e4m3x2`, `.e5m2x2`, `.ue8m0x2`, etc.) with lane-wise scaling, optional `.satfinite`/`.relu` modifiers, and explicit `.rs` rounding bits when stochastic rounding is required.  For the packed formats the destination register is still `.b32`/`.b16`, but PTX splits the conversion so that the upper bits carry the first lane and the lower bits carry the second lane, allowing the kernel writer to emit a single instruction that both clamps and writes two outputs.  Many of the saturation-focused conversions (`cvt.rn.satfinite{.relu}.{e2m1x2,.../.bf16x2}`, `cvt.{rz/rp}.satfinite.ue8m0x2`, and the `s2f6x2` scaling with a two-element `scale-factor` encoded as two `ue8m0` values) were introduced in PTX 9.1/9.2 and require Blackwell-class targets, so they can directly replace software clamps when forming quantized or flexpoint outputs.citeturn7view0

## Vector memory, caching, and stores
Vector operants such as `.v2/.v4/.v8` can be used on both loads and stores, and `ld.global`/`st.global` support the same braces-based syntax (`{a,b,c,d}`) for packing registers viewable as lanes.  The documentation also highlights `ld.global.nc` with `.vec` qualifiers, `.level::cache_hint`, `.level::prefetch_size` entries in 64B/128B/256B increments, and `.levelN::eviction_priority` which, on `sm_100`, may be combined with `.v8`/`.v4` loads to keep prefetch bandwidth high.  Analogous qualifiers exist on `st.global` (and even `st.async.vec`) so that the epilogue can write multiple lanes with a single instruction while hinting at cache policy.  Non-coherent loads plus the `.level2::eviction_priority` hints require at least `sm_100`, matching the Blackwell family.citeturn4view0turn5view0turn6view0

## Epilogue context and actionable thoughts
The optimized ws matmul epilogue currently uses `gl` to load `acc_bufs` (laid out via `blackwell.TensorMemoryLayout`), scale them with `gl.fma`, run `ws_base.swiglu` (which reshapes, converts to float32, clamps via `gl.minimum`/`tl_core.clamp`, and calls `libdevice.fast_expf`), divides by the output reciprocal, and conditionally clamps to the flexpoint infinity band before converting to `out_desc.dtype` and storing via `gl.store`.  That means we already traverse the same data twice: once to run Swiglu and once to emit the masked output, so the assembly emitted for those paths controls both compute and memory pressure.  The following ideas blend the PTX features above with the existing Gluon/Blackwell helpers `[python/perf/matmul_ws_optimized.py](/root/code/triton-ws-opt/python/perf/matmul_ws_optimized.py)` and `[python/perf/matmul_ws.py](/root/code/triton-ws-opt/python/perf/matmul_ws.py)`.

- Repack the accumulator tiles so that each register holds two `f32` lanes (for example, guarantee that `split_layout`/`bias_layout` are aligned to 64-bit boundaries and treat each logical scalar `out` as a 2-lane vector).  That lets the compiler lower the `gl.fma`, `gl.minimum`, and `tl_core.clamp` in the Swiglu pipeline into the `.f32x2` variants, cutting the instruction count in half for those arithmetic-heavy operators while staying within the `sm_100` requirement.citeturn3view0
- Replace the scalar clamp (`FLEXPOINT_SATURATE_INF`) and manual dtype conversion with a packed `cvt.rn.satfinite{.relu}` sequence that converts directly into the desired output type (e.g., `bf16x2`, `tf32`, or even `ue8m0x2`) so the hardware performs both the clamp and any quantization in one instruction.  The PTX `cvt` semantics already accept a two-lane `scale-factor` for `s2f6x2`/`ue8m0x2` and can forward `NaN` propagation or `MAX_NORM` saturations with the `.satfinite`/`.relu` modifiers, matching the flexpoint clamp semantics without extra scalar compares.citeturn7view0
- Use the vectorized and cached memory primitives when reading/writing bias, scales, or outputs: align the pointer arithmetic so that `gl.store` can emit `st.global.v4`/`st.async.vec` and bring bias/scale data into registers via `ld.global.nc.vec` with `.level2::prefetch_size` hints.  The PTX doc shows how those forms accept cache policies and non-coherent hints on `sm_100`, giving the epilogue more control over write bandwidth when streams are wide.citeturn4view0turn5view0turn6view0
